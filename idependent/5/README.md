
# Самостійна робота № 5

**Тема:** Програмування мікроконтролерів PIC16 мовою Асемблер

## Мета роботи

Ознайомитися з особливостями компілятора HI-TECH, форматом команд мови Асемблер, призначенням директив, структурою програми, засобами компонування та методами відлагодження програм для мікроконтролерів PIC16.

## Контрольні питання до лекції 5

### 1. Які особливості компілятора HI-TECH?

HI-TECH — це сімейство інструментів для розроблення програмного забезпечення вбудованих систем. Компілятор HI-TECH C використовувався для створення програм мовою C для мікроконтролерів PIC компанії Microchip.

До його основних особливостей належать підтримка архітектури мікроконтролерів PIC, оптимізація програмного коду, робота з апаратними регістрами та можливість використання мови C для розроблення вбудованих програм.

Компілятор перетворює вихідний текст програми в об'єктний код, який надалі компонують і перетворюють на файл для програмування мікроконтролера. Також інструменти HI-TECH підтримують роботу з директивами, заголовними файлами та бібліотеками.

Сьогодні для багатьох мікроконтролерів PIC використовують інструменти MPLAB XC, які прийшли на зміну старішим компіляторам HI-TECH. Проте принципи компіляції, компонування та налагодження залишаються подібними.

### 2. Формат запису команд мовою Асемблер.

Команди мови Асемблер записуються відповідно до визначеного формату. Зазвичай рядок програми може містити мітку, мнемоніку команди, операнди та коментар.

Загальна структура рядка має такий вигляд:

```asm
МІТКА:   КОМАНДА   ОПЕРАНДИ   ; Коментар
```

- **Мітка** — назва, яка позначає певну адресу програми та може використовуватися для переходів.
- **Команда** — мнемонічне позначення операції, яку потрібно виконати.
- **Операнди** — дані, регістри або адреси, з якими працює команда.
- **Коментар** — пояснення до коду, яке не виконується процесором.

Наприклад:

```asm
START:   MOVLW   0x05      ; Завантаження числа 5 у W
         MOVWF   0x0C      ; Запис W до регістра за адресою 0x0C
         GOTO    START     ; Перехід до мітки START
```

Такий формат полегшує читання програми та допомагає зрозуміти послідовність виконання команд.

### 3. Що таке псевдо команди(директиви)та якуроль виконують?

Псевдокоманди, або директиви, — це спеціальні вказівки для асемблера, які визначають порядок обробки вихідного тексту програми. На відміну від звичайних команд процесора, директиви переважно не виконуються мікроконтролером безпосередньо.

Директиви використовуються для визначення початкових адрес програмних секцій, оголошення змінних і констант, вибору цільового мікроконтролера, підключення файлів та налаштування параметрів асемблювання.

Наприклад, директиви ORG та EQU дають змогу визначити адресу розміщення коду й задати символічне ім'я для константи. Завдяки директивам програма стає зрозумілішою, а її структура — впорядкованішою.

### 4. Яке призначення директиви ORG?

Директива ORG (Origin) задає адресу в пам'яті програм або даних, з якої асемблер повинен розміщувати наступний код чи дані. Її використовують для визначення початкового розташування певної частини програми.

Наприклад:

```asm
ORG 0x0000
GOTO START

ORG 0x0005
START:
    MOVLW 0x01
```

У цьому прикладі перша команда розміщується за адресою 0x0000, а мітка START починається за адресою 0x0005. Для конкретного мікроконтролера потрібно враховувати його архітектуру та вимоги до розміщення коду.

Директива ORG допомагає правильно організувати пам'ять програм і розміщувати код у потрібних адресних областях.

### 5. Яке призначення директиви EQU?

Директива EQU використовується для присвоєння символічного імені певному числовому значенню або виразу. Вона дає змогу замінювати числові константи зрозумілими назвами.

Наприклад:

```asm
COUNT EQU 0x0C
VALUE EQU 0x05
```

У цьому прикладі COUNT відповідає значенню 0x0C, а VALUE — значенню 0x05.

Після цього символічні імена можна використовувати в командах програми. Це робить код зрозумілішим, полегшує його редагування та зменшує кількість помилок. EQU не виділяє окрему комірку пам'яті, а визначає символічну константу для асемблера.

### 6. Яка Структура Програми?

Програма для мікроконтролера PIC16 мовою Асемблер складається з кількох логічних частин. Вони забезпечують правильне налаштування мікроконтролера, виконання команд і завершення або повторення потрібного алгоритму.

Зазвичай програма містить такі елементи:

- **Заголовок** — коментарі з назвою програми, автором і коротким описом.
- **Директиви налаштування** — визначають модель мікроконтролера та параметри конфігурації.
- **Оголошення констант і змінних** — задають символічні імена та області зберігання даних.
- **Початкова адреса програми** — визначає місце розташування коду за допомогою ORG.
- **Вектор скидання** — містить команду переходу до основної програми.
- **Основна програма** — виконує необхідні дії та обробляє дані.
- **Підпрограми** — використовуються для повторюваних операцій.
- **Завершення або цикл** — визначає подальшу поведінку програми.

Приклад спрощеної структури:

```asm
        LIST    P=16F84A
        INCLUDE <P16F84A.INC>

        ORG     0x0000
        GOTO    START

START:
        MOVLW   0x05
        MOVWF   PORTB

MAIN:
        GOTO    MAIN

        END
```

Це лише приклад структури. Для реальної роботи з портами необхідно додатково налаштувати напрямок їхніх ліній, а конфігурацію мікроконтролера задавати відповідно до вимог конкретного проєкту.

### 7. За допомогою яких додаткових засобів вихідний текст компонується вихідний
модуль?

Для створення готової програми мікроконтролера використовують кілька інструментів розроблення. Вони перетворюють вихідний текст у машинний код і об'єднують необхідні частини програми.

Основними засобами є:

- **Препроцесор** — обробляє директиви включення файлів і макроси, якщо вони використовуються.
- **Компілятор або асемблер** — перетворює вихідний текст програми на об'єктний код.
- **Компонувальник (Linker)** — об'єднує об'єктні модулі та бібліотеки, розподіляє програмний код і дані в пам'яті.
- **Бібліотеки** — містять готові функції та допоміжний код, які можуть використовуватися програмою.
- **Засоби формування вихідного файлу** — створюють файл у форматі, придатному для програмування мікроконтролера, наприклад HEX.

У результаті роботи цих засобів отримують файл прошивки, який можна завантажити в пам'ять програм мікроконтролера. Для розроблення зазвичай застосовують інтегроване середовище MPLAB X IDE та відповідні інструменти Microchip.

### 8. Як Відбувається Відлагодження Програм?

Відлагодження програм — це процес перевірки правильності роботи програми та пошуку помилок у її коді. Воно допомагає встановити причину неправильної поведінки мікроконтролера й перевірити відповідність результатів очікуваним.

Основні етапи відлагодження:

1. Перевірка вихідного коду на синтаксичні помилки.
2. Асемблювання або компіляція програми.
3. Компонування об'єктних модулів і формування файлу прошивки.
4. Перевірка роботи програми за допомогою симулятора або апаратного налагоджувача.
5. Використання точок зупинки для перевірки виконання окремих команд.
6. Перегляд значень регістрів, змінних і пам'яті під час виконання програми.
7. Виправлення знайдених помилок і повторна перевірка.

Для відлагодження програм PIC16 можна використовувати MPLAB X IDE, симулятор та сумісні апаратні налагоджувачі й програматори. Симулятор дає змогу перевірити логіку програми без фізичного мікроконтролера, а апаратне налагодження допомагає перевірити роботу пристрою в реальних умовах.
